VirtualQuest × ΣLang · Case Study

口径语义层：NL2SQL 口径错误率下降 94%

把 ΣLang 确定性语义规约注入 VirtualQuest（NL2SQL 平台）的提问链路后， 同一批 30 条口径问题的口径类错误率从 56.7% 降至 3.3%。

一、实验设计

项说明
平台VirtualQuest（Vanna 2.0.2 + DeepSeek v4-flash + ChromaDB）
干预ΣLang 口径语义层：① system prompt 注入"业务口径铁律"段（方式 A）② 生成 SQL 后口径语义校验（M3）③ 评分口径因子
评测集30 条口径问题 × 5 概念（GMV / 放款笔数 / 逾期率 / 活跃用户 / ARPU），每条含直达问法、变体、易混淆问法
对照同一批问题、同一模型：--without-spec（基线）vs --with-spec（集成后）
口径类错误 = 生成 SQL 的语义（表/过滤/聚合）与口径规约定义不一致。评测不写 history 表、不污染线上数据。

三、关键观察

观察证据
口径语义层有效性（内部对照）集成后：spec 命中的问题 96% 正确，未命中的 5 条 0% 正确——同一模型、同一批问题，差异只来自"有没有口径语义层"
M3 校验真实拦截问题 29（ARPU 分母口径）生成错误 SQL，spec_check 精确报出"概念 active_users 缺少基准过滤 order_status"
最大增益在"命中后"基线命中后通过率仅 19%（prompt 里没有口径定义时，模型自由发挥）；注入铁律后 96%
剩余缺口是覆盖而非质量5 条未命中全因问法不在 aliases（"放款金额""逾期金额占比"等）——补 aliases 即可继续提升命中率

四、限制与后续

限制

  • 基线总正确率无法评分（LLM 评分服务降级），对比仅覆盖口径类错误率（计划核心指标）
  • 单次实验（30 条 × 1 轮），未做多轮稳定性验证
  • 基线 4 条 SQL 生成异常，口径错误率是下限估计

后续动作

  • 补 aliases（5 条未命中问法）→ 预期命中率 83% → 95%+
  • 多轮复测（3 轮 × 30 条）验证稳定性
  • 将评测纳入 vq CI（run_eval.py 已支持 --resume / --limit）
